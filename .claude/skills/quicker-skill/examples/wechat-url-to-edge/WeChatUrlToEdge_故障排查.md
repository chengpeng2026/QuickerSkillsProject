# 微信→Edge URL提取器 — 故障排查手册

## 故障级别1：动作完全无反应（无弹窗、无日志）

### 1.1 Quicker模块未正确配置

**症状**：触发动作后什么都没发生，Edge 没打开、无消息框。

**排查步骤**：
1. 打开动作编辑器，确认 PowerSell 模块已添加
2. 双击模块 → 确认脚本内容已粘贴
3. 确认 **运行窗口样式** 不是 `隐藏且不等待`（应选 `隐藏`）
4. 确认超时 >= 10秒

### 1.2 PowerShell 执行策略阻止

**症状**：模块执行被阻止，Quicker 可能无错误提示

**修复**：
```powershell
# 以管理员身份运行 PowerShell，执行：
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

Quicker 使用 `-ExecutionPolicy Bypass` 启动 PowerShell，正常不受影响，但某些企业域策略可能覆盖此设置。

### 1.3 动作触发了但被沙盒/防病毒拦截

**症状**：动作日志显示模块已执行，但脚本未运行

**修复**：
- 在 Windows 安全中心 → 病毒和威胁防护 → 排除项 → 添加 `C:\Program Files\Quicker\`
- 如果是公司电脑，联系 IT 将 Quicker 加入白名单

## 故障级别2：剪贴板为空（URL未获取到）

这是最常见的问题，可能原因有多个。

### 2.1 输入法干扰 ⭐⭐⭐（最高频）

**症状**：弹窗提示"未能获取到有效网页链接"，日志显示剪贴板为空或内容异常

**原理**：中文输入法（搜狗/微软拼音/QQ拼音）监听键盘时，`Ctrl+L` / `Ctrl+C` 的修饰键被输入法拦截或转换

**修复方案（按优先级）**：

| 方案 | 操作 | 效果 |
|------|------|------|
| **A. 开 Escape 保护** | 脚本中 `$ESCAPE_BEFORE_ACTION = $true` | 先退输入法再发快捷键 |
| **B. 切换纯英文** | 动作触发前手动 `Win+Space` 切英文 | 100%解决 |
| **C. 切换键盘布局** | 增强版 `$SWITCH_IME_TO_EN = $true` | 自动切换（需系统支持） |
| **D. 更换输入法** | 尝试微软拼音旧版（兼容性更好） | 根治 |
| **E. 关输入法快捷键** | 搜狗设置→高级→系统快捷键→取消Ctrl相关 | 减少冲突 |

### 2.2 延时不足 ⭐⭐

**症状**：偶尔成功、偶尔失败，低配电脑或远程桌面更明显

**修复**：
```powershell
# 低配电脑 / 远程桌面 / 虚拟机 — 加倍延时
$DELAY_BEFORE_CTRL_L = 400   # 原200
$DELAY_BETWEEN_KEYS  = 200   # 原100
$DELAY_BEFORE_CLIP   = 400   # 原200
```

**调优原则**：
1. 从大延时开始验证 → 确认能稳定工作
2. 再逐步减小延时到临界值
3. 保留 20% 余量防止偶发失败

### 2.3 微信版本更新后 Ctrl+L 行为改变 ⭐

**症状**：之前正常工作，微信更新后失效

**修复**：
1. 增强版已做 F6 + Ctrl+L 双保险
2. 如果仍失效，测试微信当前版本的地址栏快捷键：
   - 在微信浏览器内手动按 `Ctrl+L` 看是否聚焦地址栏
   - 尝试 `F6`、`Alt+D`(部分版)、`Ctrl+K`(部分版)
3. 在脚本 `Invoke-UrlCopySequence` 中添加新的快捷键行

### 2.4 页面未完全加载

**症状**：刚打开链接立刻触发动作为空白

**修复**：等加载条走完/页面内容出现后再触发动作

## 故障级别3：URL校验失败（获取到了内容但判为无效）

### 3.1 复制的是非HTTP内容

**日志示例**：`剪贴板内容: about:blank`

**原因**：微信内置浏览器可能先打开 `about:blank` 再跳转，动作在跳转前执行了

**修复**：等页面加载完成后再触发

### 3.2 复制内容带特殊字符

**日志示例**：`剪贴板内容: https://mp.weixin.qq.com/s/xxx  (结尾有NBSP空格)`

**原因**：微信文章URL末尾可能有不可见空格

**修复**：增强版已做 `\p{C}` 控制字符清理和零宽字符移除

### 3.3 复制内容不止URL

**日志示例**：`剪贴板内容: 这篇文章很好 https://example.com 分享给你`

**修复**：增强版已内建URL正则提取，基础版也会尝试提取

## 故障级别4：Edge无法启动

### 4.1 Edge未安装或非标准路径

**症状**：日志显示"无法定位 msedge.exe"

**修复**：
```powershell
# 手动在脚本中添加你的 Edge 路径
$EDGE_PATHS = @(
    "D:\MyApps\Edge\msedge.exe",   # ← 添加你的实际路径
    "C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe",
    # ... 其他默认路径
)
```

查找Edge路径：
```powershell
# PowerShell 中执行
(Get-ItemProperty "HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\App Paths\msedge.exe").'(default)'
```

### 4.2 Edge启动但URL参数错误

**症状**：Edge 打开了但显示空白页或搜索页

**原因**：URL 中的 `&` 等特殊字符被错误解析

**修复**：增强版已使用 `"` 引号包裹 URL + `Start-Process -ArgumentList` 方式，避免 shell 解析

## 故障级别5：多微信/企业微信场景

### 5.1 微信多开 — 识别了错误的微信实例

**症状**：Edge 打开的不是当前浏览的页面URL

**原因**：多开时有多个微信进程窗口，脚本选择了第一个（可能是后台的）

**修复**（增强版）：
```powershell
# 在 Find-WeChatBrowserWindow 末尾，修改排序逻辑：
# 改为按窗口可见性 + 标题长度排序
$target = $browserWindows | Sort-Object { $_.Title.Length } -Descending | Select-Object -First 1
```

### 5.2 企业微信内置浏览器窗口标题特征不同

**症状**：企业微信的浏览器窗口没被识别

**修复**：确认脚本中 `$WECHAT_PROCESS_NAMES` 包含 `WXWork`（已默认包含）

## 故障级别6：性能优化专项

### 6.1 确定最佳延时值的测试方法

```powershell
# 在脚本开头添加测试模式变量
$TEST_MODE = $true   # 测试模式：每次只做一步，日志详细

# 测试流程：
# 第1步：只测试窗口检测 → 看到日志"找到目标窗口"
# 第2步：加入窗口激活 → 确认前台切换成功
# 第3步：加入按键模拟 → 手动检查剪贴板是否有URL
# 第4步：加入Edge启动 → 全程测试
```

| `[DEBUG]` | 调试信息（增强版） |

## 终极自检清单

在向他人求助前，按此清单自查：

- [ ] Quicker 版本 >= 1.38.x
- [ ] PowerShell 版本 >= 5.1 (`$PSVersionTable.PSVersion`)
- [ ] Edge 浏览器已安装
- [ ] 微信版本为最新PC版
- [ ] 微信内置浏览器中有实际网页（非空白页/设置页）
- [ ] `$ESCAPE_BEFORE_ACTION = $true` 已开启
- [ ] 脚本中的延时参数已根据电脑性能调整
- [ ] 模块运行窗口样式设置为"隐藏"
- [ ] 超时设置为 >= 15秒
- [ ] 已关闭中文输入法测试一次
