# 电子发票二维码识别下载

> **扫码即下载** — 选一张发票图片，自动识别二维码、提取查验链接、智能下载 PDF/OFD 原件到指定目录。

---

## 🎯 一句话概括

把「扫码 → 复制链接 → 打开浏览器 → 找到下载按钮 → 另存为」的 5 步手动流程，压缩为「选图 → 选目录」两步。

---

## ❓ 为什么需要这个动作

电子发票（增值税发票、全电发票）上的二维码扫出来是一个**税务查验平台页面**，不是文件直链。税务局出于安全考虑，把真实下载链接藏在页面的 HTML、JavaScript、JSON 数据、甚至 iframe 里。不同省份的税局平台又各不相同——河南有河南的技术中台，全国统一平台又有自己的 API。

手动处理的话，每张发票都要：扫码 → 浏览器打开 → 等页面加载 → 在页面里找隐藏的「下载」按钮 → 选目录保存。对财务人员来说，一天处理几十张发票，这个重复劳动非常痛苦。

这个动作用 **1064 行 C#** 实现了全自动的多层下载策略，覆盖了市面上常见的电子发票平台。

---

## ✨ 核心功能

### 1. 智能 QR 解码（双引擎降级）

- **引擎 1**：暴力扫描内存中所有已加载程序集的 `Decode(Bitmap)` 方法签名（适配任意 QR 库版本）
- **引擎 2**：动态从磁盘加载 `zxing.dll`，配置 `AutoRotate`、`TryInverted`、`TryHarder` 等增强参数，限定 `QR_CODE` 格式
- 支持 jpg / png / bmp 格式的发票图片

### 2. 五层智能下载策略（层层回退）

| 层 | 策略 | 原理 | 命中场景 |
|:--:|------|------|----------|
| **A** | 直链下载 + 文件魔数校验 | `HttpWebRequest` 带完整浏览器头 + Cookie 容器 + 自动跟随 302 重定向（最多 10 次），下载后检测 PDF/OFD/JPEG/PNG 文件头魔数 | 302 重定向到 PDF 直链的税局 |
| **B** | HTML 智能解析 + URL 推断 | 读取策略 A 下载到的响应内容，UTF-8/GBK 双编码自动检测，7 组正则模式提取真实文件链接，支持相对路径自动补全 | 查验页内含隐藏下载链接的平台 |
| **C** | WebView2 后台自动化 | 独立 STA 线程加载隐藏 WinForms 窗口 → CoreWebView2 导航到查验页 → 注入 JS 自动遍历按钮/link/iframe → 关键词匹配点击 → 拦截 `DownloadStarting` 事件保存文件 | 河南等需 JS 交互的技术中台 |
| **D** | 已知 API 枚举 | 遍历 9 种已知下载 API 路径 + `cs` 参数拼接 + `&type=pdf`/`&download=1`/`&format=pdf` 后缀尝试 | 全国统一电子发票服务平台 |
| **E** | 浏览器手动下载 | 4 层浏览器打开回退栈（`.url` 文件 → `ShellExecute` → `rundll32` → 注册表默认浏览器 → 遍历 exe 路径），Edge 自动加 `--ignore-certificate-errors-spki-list` 参数 | 所有自动策略均失败的最后保底 |

### 3. 文件安全保护

- **文件头魔数校验**：下载完成后验明正身（`%PDF` → pdf，`PK` → ofd，`FF D8` → jpg，`89 50 4E 47` → png），不是文件头就不认
- **同名自动序号**：`发票.pdf` → `发票 (1).pdf` → `发票 (2).pdf`，避免误覆盖
- **全程不修改原始图片**：只读不写，安全第一

### 4. 国内政务环境适配

- **SSL 自签名证书**：`ServerCertificateValidationCallback` 信任所有证书（税局服务器常见自签名）
- **GBK 编码兼容**：先 UTF-8 解码，检测 `�` 字符密度 > 0.5% 自动切换 GBK
- **双 UA 降级**：先 Chrome 桌面 UA，失败换 iPhone Safari UA（部分平台对移动端返回更简单页面）
- **多层浏览器打开**：`cmd /c start` 的 `&` 截断问题已通过 `.url` 文件方案规避

### 5. 用户体验细节

- 每个失败步骤都有明确弹窗提示（识别失败 / 链接无效 / 无法下载 / 无法打开浏览器）
- 下载成功或浏览器跳转有右下角 Toast 气泡通知
- 流程可随时取消（文件选择 / 目录选择对话框点取消即退出）

## 📋 使用流程

```
1. 运行动作
      ↓
2. 弹出文件对话框 → 选择电子发票图片（jpg/png/bmp）
      ↓
3. 自动识别二维码 → 提取查验链接
      ↓   识别失败？→ 弹窗提示，退出
      ↓   链接不是 http？→ 弹窗显示内容，退出
      ↓
4. 弹出目录选择框 → 指定发票原件保存位置
      ↓   取消？→ 退出
      ↓
5. 自动执行五层下载策略
      ↓   策略 A/B/C/D 命中 → Toast "下载完成 — xxx.pdf"，完成
      ↓   全部失败 → 策略 E：打开浏览器 → Toast "请在浏览器中手动下载"
```

## ⚙️ 运行环境要求

| 依赖 | 说明 |
|------|------|
| **Quicker** | 1.44.51+（Roslyn v2 脚本环境） |
| **系统** | Windows 10 / Windows 11 |
| **WebView2 Runtime** | 可选（未安装时策略 C 自动跳过，其余 4 层仍可用） |
| **网络** | 需能访问对应税局的发票查验服务器 |

**提示**：WebView2 Runtime 是 Windows 11 预装的组件，Windows 10 用户如果缺少，可以从 [微软官网](https://developer.microsoft.com/microsoft-edge/webview2/) 下载安装。安装后策略 C 的命中率会显著提升（尤其是河南等需要 JS 交互的平台）。

## ⚠️ 注意事项

1. 二维码区域需**清晰、无遮挡、无反光**，否则识别会失败
2. 下载目录需有**写入权限**（默认弹出的目录选择器可新建文件夹）
3. **不同省份税务平台差异很大**：河南、广东、四川、全国统一平台等各自的下载 API 不同。如果某个平台全部策略都失败（最终只打开浏览器），欢迎在评论区反馈发票类型和税务局名称，以便后续版本适配
4. 本动作**不修改、不上传**您的发票图片，所有操作均在本地完成

## 🧪 技术细节（给开发者）

- **语言**：C#（Quick Roslyn v2 脚本模式）
- **QR 解码**：反射调用（兼容 zxing.dll 多版本，无需编译时引用）
- **HTTP**：`HttpWebRequest` + 共享 `CookieContainer` + 完整浏览器头伪装 + GZip/Deflate 自动解压
- **编码检测**：UTF-8 → 扫描 `�` 替换字符 → 阈值切换 GBK
- **WebView2**：独立 STA 线程 + 隐藏 WinForms 宿主 + `CoreWebView2` 直接调用（不依赖 WPF）
- **浏览器打开**：4 层回退栈 + 注册表读取默认浏览器 + 遍历 8 个常见安装路径
- **文件校验**：4 字节魔数检测（PDF/OFD/JPEG/PNG）
